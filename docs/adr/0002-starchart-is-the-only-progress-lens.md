# 0002. 스타차트가 유일한 진행도 화면이다

날짜: 2026-08-24
상태: 승인됨

## 맥락

진행도 화면이 두 개가 될 뻔했다: 기존 로드맵 트래커(`/roadmap`, 16개 항목
체크)와 새 3D 스타차트(354개 성계 노드). 정크션 7개가 양쪽에 모두 존재해,
같은 사실("금성 교차점 완료")을 두 화면이 따로 기록·표시하면 어긋날 수 있다.
두 id 체계(`venus-junction` 슬러그 vs `SolNodeNN`) 사이 매핑 유지비도 든다.

대안은 셋이었다: ① 두 화면 병존 + 매핑 테이블로 동기화, ② 로드맵을 원본으로
두고 스타차트는 표시만, ③ 스타차트를 유일한 화면으로 만들고 로드맵은 콘텐츠로
흡수.

## 결정

③을 택한다. 스타차트가 유일한 진행도 화면이며, 인게임과 같은 구성(행성 목록
→ 줌인 → 노드 상세)으로 동작한다.

- 진행도의 원본은 **완료 집합** 하나 — 성계 노드 id와 비노드 목표(퀘스트·준비
  목표) 슬러그가 한 집합에 공존한다. 노드 3상태(잠김/미클리어/클리어)는
  집합 + 연결 그래프에서 파생하며 저장하지 않는다.
- 옛 로드맵의 집필 문장은 화면이 아니라 **행성 가이드** 콘텐츠로 재편된다.
  비노드 목표의 체크도 가이드 안에서 이뤄진다.
- `/roadmap` 페이지는 스타차트 완성 시점에 제거한다. 그때까지 수정하지 않는다.
- 저장 스키마는 version 2로 올린다. 미배포 상태라 마이그레이션은 하지 않는다
  — 로더가 모르는 버전을 빈 집합으로 읽으므로 v1 데이터는 자연 폐기된다.

## 결과

- 진행도 어긋남과 슬러그↔노드 매핑 유지비가 원천 제거된다.
- 프로필 JSON 가져오기(ADR 대상 아님, #27 리서치)가 SolNode id 그대로 합집합
  병합으로 흡수된다.
- 정상 동작하던 `/roadmap` 트래커·위젯 코드는 스타차트 완성까지 죽은 무게로
  남는다 — 제거 전까지 그 코드에 기능을 추가하지 않는다.
- 퀘스트 진행처럼 노드로 표현 안 되는 상태를 화면에 보이려면 반드시 행성
  가이드를 거쳐야 한다 — 가이드 콘텐츠 저작이 병목이 된다.
