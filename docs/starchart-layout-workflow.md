# 스타차트 좌표 데이터셋 — 생성·보정 워크플로

좌표는 어느 공개 소스에도 없다. 그래서 **자동 생성은 초기 배치까지**이고, 보기
좋은 배치는 좌표 JSON을 에디터에서 직접 고쳐서 만든다. 편집 UI는 만들지 않는다
([#29](https://github.com/b-wani/warframe-hub/issues/29)에서 드래그 편집·스크린샷
트레이싱 변형을 기각했다 — 프로토타입은 `prototype/starchart-layout-workflow`
브랜치에 보존).

관련: 스펙 [§3.2](specs/starchart-v1.md), 용어 [CONTEXT.md](../CONTEXT.md)

## 파일

| 파일 | 무엇 |
| --- | --- |
| `src/data/starchart-layout.json` | 좌표 데이터셋 (커밋됨, 손으로 고치는 파일) |
| `scripts/build-starchart-layout.mts` | 초기 배치 생성 + 검증 |
| `src/starchart/celestial.ts` | 천체 배치표 (궤도 순서·위성/프록시마 소속) |
| `src/starchart/force-layout.ts` | 노드 구름 force-directed 시뮬레이션 |
| `src/starchart/layout.ts` | 스키마·검증·병합 |

좌표 대상은 정제 노드 데이터셋의 **노드 352개 + 천체 29개**다. 릴레이 그룹은
지도에서 숨기므로(진행도와도 무관) 노드·그룹 모두 좌표 대상이 아니다.

## 좌표계

```jsonc
{
  "groups": { "Earth": { "x": 54, "y": -618 } },   // 성계 뷰: 원점이 태양
  "nodes":  { "SolNode12": { "x": -37, "y": 88 } } // 행성 뷰: 원점이 그룹 중심
}
```

- **천체 좌표(`groups`)** — 성계 뷰에서의 위치. 원점(0,0)이 태양이다.
- **노드 좌표(`nodes`)** — 자기 그룹 안에서의 상대 위치. 원점(0,0)이 그룹
  중심이라 천체를 옮겨도 노드 구름이 통째로 따라간다.
- 값은 정수만 받는다 — 손으로 고칠 파일이라 소수점을 두지 않는다.
- 한 좌표가 한 줄이라, 재생성 diff가 바뀐 좌표 줄만 보여준다.

## 초기 배치가 만들어지는 규칙

**천체** — 스펙 §2.1의 "실제 천문 순서"를 규칙으로 옮겼다. 행성은 궤도 순서대로
반지름이 커지고(수성 → … → 세드나 → 타우), 위성은 자기 행성 옆에, 프록시마는
자기 행성 바깥쪽에 붙는다. 반지름 순서만 천문학적으로 의미가 있고 각도는 임의다
(실제 행성도 공전한다) — 겹치지 않게 황금각으로 벌려 둔 출발점일 뿐이다.
궤도 순서가 없는 특수 구역(보이드·쿠바 요새·자리만·두비리·홀바니아)과 베일
프록시마는 마지막 궤도 바깥 고리에 균등 배치한다 — 놓을 천문학적 자리가 없으니
손보정 대상이라는 뜻이다. 프록시마 7개 중 베일만 행성에 붙지 않는데, 인게임에서도
특정 행성에 종속되지 않는 심우주 구역이기 때문이다.

**노드 구름** — force-directed 간이 시뮬레이션. 파라미터는 #29에서 눈으로 검증한
값 그대로다: 반발 12000 · 간선 스프링 90px · 중심 인력 0.003 · 300회 반복.
초기 배치가 각도 기반 고정 시드라 난수가 없고, 몇 번을 돌려도 같은 좌표가 나온다.

## 명령

```bash
pnpm build:starchart-layout              # 빠진 좌표만 채운다 (수동 보정 보존)
pnpm build:starchart-layout --regenerate # 전부 다시 계산한다 (수동 보정 폐기)
pnpm build:starchart-layout --check      # 파일을 쓰지 않고 검증만 한다
```

기본 실행은 **이미 있는 좌표를 건드리지 않는다.** 보정을 마친 뒤 실수로 다시
돌려도 손본 배치가 날아가지 않는다. `--regenerate`는 손본 것까지 전부 덮어쓰므로
diff로 확인하고 쓴다.

## 보정 워크플로

1. `src/data/starchart-layout.json`을 에디터에서 연다.
2. 옮기고 싶은 노드·천체의 `x`/`y`를 고친다.
3. `pnpm build:starchart-layout --check`로 검증한다 (빠진 좌표·고아 좌표·정수가
   아닌 값을 잡는다).
4. `pnpm dev`를 띄운 채로 저장하면 정적 임포트가 HMR로 갱신된다 — 지도에서 바로
   확인한다. (스타차트 화면이 붙기 전까지는 3번의 검증까지가 확인 수단이다.)

## 게임 패치로 노드가 바뀌었을 때

1. `pnpm build:starchart` — 정제 노드 데이터셋을 먼저 갱신한다.
2. `pnpm build:starchart-layout` — 새로 생긴 노드에만 좌표가 붙고, 사라진 노드의
   좌표는 걷어낸다. 무엇이 추가·삭제됐는지 표준 오류로 알려준다.
3. 새 노드는 같은 그룹의 다른 노드와 겹칠 수 있다 (그 그룹의 배치를 다시 돌려
   빠진 자리만 가져오기 때문이다). diff에 뜬 노드만 눈으로 확인하고 손본다.
4. 그룹 자체가 새로 생기거나 사라지면 스크립트가 실패한다 —
   `src/starchart/celestial.ts`의 천체 배치표에 궤도 순서를 넣거나 지워야 한다.

## 검증이 잡는 것

`pnpm test`(CI)와 `--check`가 같은 규칙으로 본다:

- 좌표가 없는 노드·그룹 (`노드 "SolNodeNN"의 좌표가 없다`)
- 가리킬 대상이 없는 고아 좌표 — 데이터셋에 없는 id, 릴레이 그룹의 노드
- 스키마 위반 — 정수가 아닌 값, 모르는 필드
- 천체 배치표와 데이터셋의 그룹 불일치
